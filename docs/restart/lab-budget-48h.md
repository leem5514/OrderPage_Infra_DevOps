# 48시간·8만 원 목표와 배포 전 비용 설정

2026-11-27 사용자 결정: **최대 2일 가동, 가능하면 총 8만 원 이하**. 모니터링·부하·무중단 배포 실험을 진행하며, 첫 구성은 EKS `m6i.large` 2대와 Jenkins `m6i.large` 1대를 유지한다. 아직 실측으로 입증한 최소 사양은 아니며 측정 후 축소 여부를 판단한다.

## 실제 설정에 반영한 것

Git 제외 `terraform/envs/dev/terraform.tfvars.json`의 `monthly_budget_usd`를 null에서 **45**로 변경했다. 기존 Terraform Budget 모듈을 사용하므로 별도 리소스 구현이나 새 유료 서비스를 추가하지 않았다. 새 plan은 `service-budget48-review.tfplan`이며 Git에서 제외한다.

| 항목 | 값 |
|---|---|
| Budget 이름 | orderpage-dev-account-monthly |
| 통화·기간 | USD·MONTHLY |
| 월 예산 | $45 |
| 알림 1 | 실제 누적 비용이 80%($36)를 초과할 때 |
| 알림 2 | 실제 누적 비용이 100%($45)를 초과할 때 |
| 전달 | 기존 운영 SNS topic → 확인 완료된 이메일 구독 |
| 자동 중지·자동 삭제 | 없음 |
| 최대 운영 시간 | 자원 생성부터 정리 완료까지 48시간, 운영 절차로 관리 |

**$45는 8만 원의 정확한 환산값이나 과금 상한이 아니다.** 알림이 비용 반영 지연을 가지므로 도착할 때까지 기다리며 부하를 계속 가하지 않는다. 이 Budget은 프로젝트만 필터링하지 않은 계정의 월 누적 비용을 본다. 기존 사용액이 있거나 월 경계를 넘으면 48시간 실습비와 다르다. 배포 전에 기존 월 누적액과 실제 청구 통화·세금 처리를 확인한다. 최초 서비스 생성 시각이 확정되면 KST 종료 시각을 기록한다.

공개 예제의 모니터링 비활성·Budget null 기본값은 유지한다. 실제 이메일과 계정별 입력이 없는 일반 clone에서 예산/구독을 의도치 않게 생성하지 않기 위해서다. 실제 계정 값은 PR에 포함하지 않는다.

## 비용 계산과 여유분

[서울 가격 근거](pricing-evidence/seoul-2026-11-27.json)와 기존 [계산기](../../scripts/estimate-lab-costs.mjs)를 사용했다. 아래는 48시간 내내 현재 자원을 유지하고 ALB를 운영하는 가정이다. 무료 구간·크레딧·할인은 적용하지 않았다. 환율 1,500원/USD와 10% 세금 여유분은 **계획 가정**이며 실제 결제 환율이나 개별 세금 적용을 확정한 값이 아니다.

| 사용량 가정 | 계산된 USD | 계획 원화 환산 |
|---|---:|---:|
| NAT 5GB·로그 수집 1GB·평균 1 LCU | 40.64 | 67,056원 |
| NAT 10GB·로그 수집 5GB·평균 1 LCU | 43.98 | 72,567원 |
| NAT 20GB·로그 수집 10GB·평균 2 LCU | 48.75 | 80,438원 |

일부 인터넷·AZ 간 전송, S3/ECR 요청·저장, SNS/관측 API, 로그 저장·쿼리, RDS CPU 크레딧·초과 백업, Vercel, 기존 계정 사용액과 종료 후 잔여 자원은 위 금액에서 제외된다. 사용량은 예상 시나리오이지 설정된 상한이 아니다. 따라서 8만 원 이하를 보장하지 않는다. 전체를 52시간까지 늘리면 첫 시나리오만으로도 약 72,501원이므로 생성/정리 시간을 48시간 밖에 따로 더하지 않는다.

## 48시간 안에 실험과 정리를 끝내는 순서

- **T0:** 첫 서비스 자원 생성 시각을 기록한다. 절대 종료 시각은 T0+48시간이다.
- **T0~24시간:** 설치·연결·SNS 수신·기본 모니터링을 확인하고 고정 부하 기준값을 확보한다. 설치가 지연되면 실험 범위를 줄인다.
- **24~40시간:** 같은 이미지·데이터·부하 조건으로 Recreate와 RollingUpdate+Readiness의 실패 요청·가용성·배포 시간을 비교한다. 부하 발생기는 정해진 측정 구간에만 켠다. 실험 중 노드 크기를 바꾸면 같은 비교군으로 취급하지 않는다.
- **40시간:** 새 실험을 멈추고 지표·로그·Jenkins 기록을 내보낸 뒤 정리를 시작한다. Prometheus는 영속 볼륨이 없어 먼저 증거를 보존한다.
- **48시간 전:** 앱/ALB 정리 후 Terraform 자원 삭제와 잔여 EBS/EIP/NAT/MQ 로그·ECR/S3 내용을 확인한다. EKS 노드나 EC2만 정지해도 전체 과금이 끝나는 것이 아니다.

현재 Pod 2개·maxSurge 1·maxUnavailable 0·Readiness 설정은 무중단 배포를 위한 준비 조건이다. 실제 5xx/timeout/연결 실패와 성공률을 측정하기 전에는 무중단을 달성했다고 표현하지 않는다. Jenkins 중지나 인스턴스 축소는 필요 시 별도로 검토하며 이번 비용 계산에는 반영하지 않았다.

## 새 plan과 권한 검증

새 plan에서 **생성 75개, 수정·삭제·교체 0개**를 확인했다. 이전 74개에 Budget 1개가 추가된다. SNS 정책에는 기존 코드의 조건부 Budget publish 허용이 포함될 예정이며, 최종 계산된 ARN·정책 본문은 후속 확인 대상이다.

Budget이 없는 이전 plan과, 승인 금액의 Budget이 있는 plan을 모두 검사할 수 있도록 검토 함수를 수정했다. 예상 금액과 다른 금액, 다른 계정/통화/기간, 다른 SNS 목적지와 잘못된 통지 기준을 실패 처리한다. 계산 전 목적지는 통과로 세지 않는다.

- 전체 테스트 142개 통과. 실제 plan 설정 검사 73개 통과.
- 계산 전 정책/목적지 26개 보류: 기존 24개 + Budget 알림 목적지 2개.
- 감사 권한 연결 후 통합 IAM 13개 모두 AWS ValidatePolicy findings 0건, 실제 Role당 연결 한도 20개 확인.
- 배포 Role trust와 기존 state/read 정책 기본 버전이 저장소와 일치함을 확인.
- 배포 Role에는 아직 기존 정책 2개만 연결돼 있다. 새 정책 연결과 실제 서비스 생성·SNS 수신 시험은 미실행이다.

[민감값을 제외한 새 plan 근거](security-evidence/budget48-plan-2026-11-27.json)를 보관한다. plan 성공과 AWS 정책 문법/모범 사례 검증은 실효 권한·서비스 생성 성공·지출 제한을 보장하지 않는다. 이번 작업에서는 **plan만 실행했으며 apply는 실행하지 않았다.**
